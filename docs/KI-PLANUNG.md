## 📊 Trainings-Metriken

### Loss (Fehlerrate)

```
Definition: Misst wie weit die Vorhersagen von den tatsächlichen Werten abweichen

Ziel: Möglichst niedrig (nahe 0)

Aktuell: 1.4604
Status: ✅ Exzellent (unter 2.0)
Trend: ↓ Sinkt kontinuierlich
```

### Accuracy (Genauigkeit)

```
Definition: Prozentsatz der korrekten Vorhersagen

Ziel: Möglichst hoch (nahe 100%)

Aktuell: 89.27%
Status: ✅ Sehr gut (über 85%)
Trend: ↑ Steigt kontinuierlich
Beste: 91.06% (bereits erreicht!)
```

## 🎯 Einsatzbereiche

### 1. Automatische Dienstplanung

**Szenario:** Dienstplan für nächste Woche erstellen

**Ablauf:**
```
1. Objekte & Anforderungen laden
   ↓
2. Verfügbare Mitarbeiter filtern
   ↓
3. KI bewertet Eignung (0-100%)
   ↓
4. Optimale Zuordnung berechnen
   ↓
5. Konflikte prüfen & vermeiden
   ↓
6. Vorschlag generieren
   ↓
7. Planer prüft & genehmigt ✅
```

**Ergebnis:**
- ✅ Optimale Besetzung
- ✅ Keine Konflikte
- ✅ Präferenzen berücksichtigt
- ✅ Rechtlich konform

---

### 2. Ersatzpersonalsuche

**Szenario:** Mitarbeiter sagt kurzfristig ab

**Ablauf:**
```
1. Ausfall erkennen
   ↓
2. Qualifikationen analysieren
   ↓
3. KI sucht passende Ersatzkräfte
   ↓
4. Verfügbarkeit prüfen
   ↓
5. Top-3 Kandidaten vorschlagen
   ↓
6. Automatisch benachrichtigen ✅
```

**Ergebnis:**
- ✅ Sofort Ersatz finden
- ✅ Qualifizierte Mitarbeiter
- ✅ Keine Lücken im Dienstplan

---

### 3. Skill-Matching

**Szenario:** Objekt mit speziellen Anforderungen

**Beispiel:**

Objekt: Bank-Filiale
Anforderungen:
- Bewachungserlaubnis (§34a) ✓

- Erste-Hilfe-Zertifiziert ✓
- Sicherheitsstufe 3+ ✓

KI findet Mitarbeiter die ALLE Anforderungen erfüllen ✅

---

### 4. Präferenz-Optimierung

**Szenario:** Mitarbeiter hat Präferenzen

**Beispiel:**
```
Mitarbeiter: Max Mustermann
Präferenzen:

### 5. Überstunden-Vermeidung

**Szenario:** Mitarbeiter接近 Max-Stunden

1. Aktuelle Stunden prüfen

   ↓

   ↓
4. Verbleibend: 6h
   ↓
5. KI plant nur noch max. 6h ✅
```

**Ergebnis:**
- ✅ Keine Überstunden
- ✅ Gesetzlich konform
- ✅ Mitarbeiter gesund

## 🔬 Trainings-Architektur

### Daten-Vorbereitung

```
1. Historische Daten sammeln
   - Dienstpläne der letzten 12 Monate
   - Zeiteinträge & Abrechnungen
   - Mitarbeiter-Qualifikationen
   - Objekt-Anforderungen

2. Features extrahieren
   - Mitarbeiter-Skills
   - Objekt-Anforderungen
   - Zeitliche Präferenzen
   - Konflikt-Muster

3. Labels erstellen
   - Welche Zuordnung war optimal?
   - Welche Konflikte traten auf?
   - Welche Präferenzen wurden erfüllt?

4. Train/Test Split
   - 80% Trainingsdaten
   - 20% Validierungsdaten
```

---

### Modell-Architektur

```
Input Layer:
  - Mitarbeiter-Features (50+)
  - Objekt-Features (30+)
  - Zeitliche Features (20+)
  ↓
Hidden Layers:
  - Dense Layer 1 (256 Neurons)
  - Dense Layer 2 (128 Neurons)
  - Dense Layer 3 (64 Neurons)
  ↓
Output Layer:
  - Eignungsscore (0-100%)
  - Konflikt-Wahrscheinlichkeit
  - Präferenz-Match
```

---

### Trainings-Parameter

```
Epochen: 1000
Batch Size: 32
Learning Rate: 0.001
Optimizer: Adam
Loss Function: Mean Squared Error
Early Stopping: Nach 50 Epochen ohne Verbesserung
Checkpoint Interval: Alle 100 Epochen
```
