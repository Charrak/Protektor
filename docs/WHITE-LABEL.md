## 🖼️ Logo Upload

**Spezifikationen:**
```

Max. Größe: 5 MB
Empfohlene Größe: 200x50 Pixel
```

**Verwendung:**
- ✅ Navigation (Sidebar)
- ✅ Login-Seite
- ✅ E-Mail-Templates

## 🔧 Einstellungen vornehmen

### Schritt 1: Admin-Bereich öffnen

```
Navigation: Verwaltung → White-Label Branding
```

### Schritt 2: Logo hochladen

```
1. Klick auf "Logo hochladen"
2. Datei auswählen (max. 5 MB)
3. Vorschau prüfen
4. Speichern
```

### Schritt 3: Favicon hochladen

```
1. Klick auf "Favicon hochladen"
2. Datei auswählen (max. 5 MB)
3. Vorschau prüfen
4. Speichern
```

### Schritt 4: Brand Color wählen

```
1. Klick auf Farbwähler
2. Farbe auswählen ODER
3. HEX-Code eingeben (#RRGGBB)
4. Vorschau prüfen
5. Speichern
```

### Schritt 5: Login Message eingeben

```
1. Textfeld ausfüllen
2. Max. 500 Zeichen
3. Vorschau prüfen
4. Speichern
```

### Schritt 6: Alles speichern

```
Klick auf "Einstellungen speichern"
Fertig! ✅
```

## 💡 Best Practices

### Logo

```
✅ Transparenter Hintergrund (PNG)
✅ Gute Auflösung (min. 200x50px)
✅ Einfaches Design (erkennbar in klein)
✅ Corporate Design beachten
✅ Keine komplexen Details

❌ Zu klein (nicht lesbar)
❌ Zu komplex (nicht erkennbar)
❌ Schlechte Qualität (pixelig)
```

### Favicon

```
✅ Quadratisch (32x32px oder 64x64px)
✅ Einfaches Icon oder Buchstabe
✅ Kontrastreich
✅ Wiedererkennbar in klein

❌ Zu detailliert (nicht erkennbar)
❌ Zu klein (16x16px minimum)
❌ Komplexe Grafiken
```

### Brand Color

```
✅ Corporate Design Farbe
✅ Gute Lesbarkeit auf weiß
✅ Kontrastreich genug
✅ Konsistent mit Logo

❌ Zu hell (schlecht lesbar)
❌ Zu dunkel (drückend)
❌ Neon-Farben (unprofessionell)
```

### Login Message

```
✅ Persönlich & einladend
✅ Kurz & prägnant
✅ Motivierend
✅ Firmen-Kultur widerspiegeln

❌ Zu lang (max. 500 Zeichen)
❌ Generisch (nicht persönlich)
❌ Negative Formulierungen
```

## 🎯 Use Cases

### Use Case 1: Neue Firma onboarden

**Szenario:** Neue Sicherheitsfirma wird Kunde

**Ablauf:**
```
1. Tenant erstellen (Platform Admin)
2. E-Mail geht an Kunde mit "Passwort wählen" Button
3. Kunde setzt Passwort
4. Kunde loggt sich ein
5. Kunde geht zu "White-Label Branding"
6. Kunde lädt Logo hoch
7. Kunde wählt Brand Color
8. Kunde gibt Login Message ein
9. Fertig! ✅
```

**Ergebnis:**
- ✅ Kunde sieht sein Logo
- ✅ Fühlt sich wie "eigene" Software
- ✅ Professioneller Eindruck

---

### Use Case 2: Rebranding

**Szenario:** Firma ändert ihr Logo/Design

**Ablauf:**
```
1. Admin geht zu "White-Label Branding"
2. Klickt "Logo löschen"
3. Lädt neues Logo hoch
4. Ändert Brand Color (falls nötig)
5. Aktualisiert Login Message
6. Speichert
7. Sofort überall aktiv! ✅
```

**Ergebnis:**
- ✅ Neues Design sofort aktiv
- ✅ Keine Downtime
- ✅ Alle Benutzer sehen neues Design

---

### Use Case 3: Saisonales Branding

**Szenario:** Weihnachts-Design

**Ablauf:**
```
Dezember:
1. Logo mit Weihnachts-Elementen hochladen
2. Brand Color: Rot/Grün
3. Login Message: "Frohe Weihnachten!"

Januar:
1. Zurück zu normalem Design
2. Standard-Logo wieder hochladen
3. Brand Color zurücksetzen
4. Login Message entfernen
```

**Vorteile:**
- ✅ Flexible Anpassung
- ✅ Saisonale Akzente
- ✅ Mitarbeiter-Motivation

## 🔐 Sicherheit

### Dateityp-Prüfung

```
Erlaubte Formate:
✅ image/jpeg
✅ image/png
✅ image/gif
✅ image/webp
✅ image/svg+xml

Nicht erlaubt:
❌ Executable Dateien
❌ Scripts
❌ Potenziell schädliche Dateien
```

### Dateigrößen-Limit

```
Max. 5 MB pro Datei
✅ Verhindert Missbrauch
✅ Schützt vor DoS
✅ Schnellere Uploads
```

### Speicherung

```
✅ Lokal auf Server (uploads/)
✅ Docker Volume (persistent)
✅ Tenant-isoliert
✅ Keine Cloud-Abhängigkeit
```

### Zugriffskontrolle

```
✅ Nur Tenant-Admins können Branding ändern
✅ Authentication erforderlich
✅ Audit-Log für alle Änderungen
✅ Keine unbefugten Änderungen
```

## 📋 Technische Details

### Datenbank-Schema

```sql
-- Tenant Branding Fields
logoUrl VARCHAR(500)
faviconUrl VARCHAR(500)
brandColor VARCHAR(7)
loginMessage VARCHAR(500)
```

### API-Endpunkte

```
GET    /api/v1/branding/branding           - Branding-Einstellungen holen
PUT    /api/v1/branding/branding           - Branding aktualisieren
POST   /api/v1/branding/branding/logo      - Logo hochladen
DELETE /api/v1/branding/branding/logo      - Logo löschen
POST   /api/v1/branding/branding/favicon   - Favicon hochladen
DELETE /api/v1/branding/branding/favicon   - Favicon löschen
```

### Frontend-Komponenten

```
BrandingSettingsPage.tsx    - Einstellungen UI
branding.service.ts         - API Service
Layout.tsx                  - Navigation mit Logo
LoginPage.tsx               - Login mit Logo & Message
```

## 🎓 Verwaltung

### Für Tenant-Admins

```
Berechtigung: Tenant Admin
Zugang: Verwaltung → White-Label Branding
Aktionen:
- Logo hochladen/löschen
- Favicon hochladen/löschen
- Brand Color ändern
- Login Message ändern
- Alles speichern
```

### Für Platform-Admins

```
Platform-Admins können:
- Tenant-Branding einsehen (read-only)
- Keine direkten Änderungen
```


### Für Support

**Häufige Fragen:**

**Q: "Wie ändere ich mein Logo?"**
```
A: Verwaltung → White-Label Branding → Logo hochladen
```

**Q: "Welche Größe sollte mein Logo haben?"**
```
A: 200x50 Pixel für Navigation, 32x32 für Favicon
```

**Q: "Kann ich verschiedene Logos für verschiedene Bereiche?"**
```
A: Nein, ein Logo für alle Bereiche (einheitliches Design)
```

**Q: "Was passiert mit meinem alten Logo?"**
```
A: Wird automatisch gelöscht wenn neues hochgeladen wird
```
